# Clipzy nginx HTTPS gateway (pull-only stack)

**Date:** 2026-09-14  
**Status:** Approved (approach 1 — nginx :443 + self-signed, swapable certs)  
**Goal:** Other machines run Clipzy by pulling images; host exposes **only port 443**. Frontend and backend are image-only (no host ports).

## Context

Today `docker-compose.pull.yml` publishes frontend `:3000`, backend `:8081`, MinIO `:9000/:9001`, Postgres `:5433`. The frontend image bakes `NEXT_PUBLIC_API_URL=http://localhost:8081`. Media uses `S3_PUBLIC_BASE_URL=http://localhost:9000/videos`.

We want a single HTTPS entrypoint for install-on-another-machine and a path to real certs later.

## Decisions (approved)

| Decision | Choice |
|----------|--------|
| Public port | **443 only** |
| TLS | Self-signed certs shipped / generated; optional volume mount for real certs later |
| Frontend / backend | **GHCR images only**; no `ports:` on host |
| Postgres / MinIO | Internal Docker network only (no host publish) |
| App routing | Same-origin via nginx path prefixes |

## Architecture

```
Browser
  │
  │  https://localhost/          (UI)
  │  https://localhost/api/...   (API)
  │  https://localhost/videos/... (media / uploads)
  ▼
nginx:443
  ├── /api/     → backend:8081/   (strip /api prefix)
  ├── /videos/  → minio:9000/videos/
  └── /         → frontend:3000/
        │
        ├── backend ↔ postgres:5432
        └── backend ↔ minio:9000 (S3 API, internal)
```

## Nginx

- Official `nginx:alpine` (or `nginx:1.27-alpine`).
- Config in repo: `infra/nginx/nginx.conf` (+ optional `infra/nginx/certs/`).
- Listen `443 ssl`; HTTP→HTTPS redirect on **80** is **out of scope for v1** unless needed for ACME later (document as follow-up). For v1, only publish `443:443`.
- Self-signed: `infra/nginx/certs/fullchain.pem` + `privkey.pem` generated by a small script or committed placeholder + entrypoint that generates if missing.
- Real certs later: mount over `/etc/nginx/certs` without changing routes.
- Proxy headers: `Host`, `X-Forwarded-For`, `X-Forwarded-Proto`, `X-Forwarded-Prefix` as needed.
- Large body / long timeouts for video upload and HLS (`client_max_body_size`, `proxy_read_timeout`).

## Image / env contract

### Frontend (rebuild GHCR)

| Build arg | Value |
|-----------|--------|
| `NEXT_PUBLIC_API_URL` | `https://localhost/api` |

CI (`.github/workflows/docker-images.yml`) must change from `http://localhost:8081` to `https://localhost/api`.

Runtime `environment:` cannot override `NEXT_PUBLIC_*` (already baked). New tag/`latest` required after CI runs.

### Backend (env in compose)

| Variable | Value |
|----------|--------|
| `CLIPZY_CORS_ORIGINS` | `https://localhost` |
| `S3_PUBLIC_BASE_URL` | `https://localhost/videos` |
| `S3_ENDPOINT` | `http://minio:9000` (internal) |
| No host `ports` | — |

### Presigned uploads

Browser PUTs must hit a host it can reach. Design:

1. Prefer configuring the S3 client/presigner so generated PUT URLs use the **public** base (`https://localhost/videos/...` or path-style under that host), **or**
2. Nginx proxies MinIO path-style API under `/videos/` so browser PUT/GET work through 443.

Implementation must verify one end-to-end upload + playback through nginx; if the AWS SDK still emits `http://minio:9000`, add an endpoint/public-URL fix in backend (small code change) as part of this work.

## Compose changes (`docker-compose.pull.yml`)

- Add `nginx` service: image + config + certs volumes; `ports: ["443:443"]`; `depends_on: frontend, backend, minio`.
- `frontend` / `backend`: remove `ports:`; keep `image: ghcr.io/...` only (no `build:`).
- `postgres` / `minio`: remove host `ports:`.
- Keep volume names for data persistence.
- Header comments: curl pull compose → `docker compose pull && up -d` → open `https://localhost/en` (accept cert warning).

Optional later: align root `docker-compose.yml` (build-from-source) with the same nginx topology for local parity — **not required** for this slice; pull file is the install path.

## Docs

- Update `README.md` / `DEPLOY.md`: single URL `https://localhost/en`, cert warning, GHCR public/login note, how to replace certs.
- Stop advertising host ports 3000/8081/9000 for the pull stack.

## Success criteria

1. `docker compose -f docker-compose.pull.yml up -d` (after image rebuild) exposes **only 443** for app traffic.
2. UI loads at `https://localhost/en` (browser may warn on self-signed).
3. API calls go to `https://localhost/api/...` and succeed (register/login smoke).
4. Upload + HLS playback work via `https://localhost/videos/...` (or documented interim limitation if deferred with explicit follow-up).
5. Frontend/backend remain GHCR image-only services.

## Non-goals (this slice)

- Let’s Encrypt / ACME automation
- Publishing port 80
- Multi-domain / production CDN cutover
- Changing Postgres credentials model

## Follow-ups

- ACME (approach 2) or mount production PEMs (approach 3)
- Optional HTTP :80 → HTTPS redirect
- Parameterize public hostname (not only `localhost`) via compose env for LAN IP / domain
